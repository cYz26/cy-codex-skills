# DevFlow 0.4.0

DevFlow 0.4.0 centralizes Human-Gate decisions around material authority deltas. Approved local, reversible, deterministic work continues without phase-boundary prompts; exact task-owned generated artifacts can be cleaned automatically after their owner exits; ambiguous identity, scope, ownership, or risk still fails closed.

The release also adds a recoverable milestone state machine. A Goal-bound contract can cover one exact commit, fast-forward-only push, immutable tag-bound publication, public asset readback, receipt-bound fast-forward of one named clean DevFlow source checkout, and its named cache/project refresh without repeated authorization. Every effect is bound to the reviewed candidate and an after-effect readback receipt. PR creation, merge, force-push, OpenSpec archive, unnamed consumers, and unrelated releases remain excluded.

Candidate eligibility now re-reads strict candidate-contained validation and independent-review evidence, rejects forged receipt projections and non-canonical commands, and applies the same strict standing-contract validator at every authorization seam. Runtime and plugin archives use compression-independent stored members with fixed metadata; the tag-bound publication workflow verifies the locally frozen seven-asset name/size/SHA-256 expectation before it can create the immutable GitHub Release.

Compatibility is default-deny. Existing projects receive no standing milestone authority merely by upgrading, project schema remains at 8, historical user files are never selected for automatic cleanup, and legacy side-effect callers retain their exact-string authorization behavior.
