## Why

DevFlow's sixteen published skills each pass Plugin Eval individually, but the
release plugin remains 86/B with heavy aggregate trigger, invoke, and deferred
budgets. The portfolio also contains supporting files that are not linked from
their owning `SKILL.md`, while several high-cost skills repeat low-frequency
commands and safety detail in the always-loaded body.

## What Changes

- Classify every published DevFlow skill by distinct workflow ownership,
  routing, scripts, tests, packaging, and compatibility obligations before
  changing its delivery.
- Preserve all sixteen public skill names because current evidence does not
  prove any complete skill is unused or compatibility-safe to remove.
- Keep essential workflow and selection instructions in `SKILL.md`, and move
  conditional operational detail into directly linked, one-level references
  that state exactly when they must be read.
- Remove supporting files only when they have no live link, contain no unique
  contract, and are duplicated by canonical DevFlow/OpenSpec guidance.
- Add regression coverage for the public portfolio, reachable supporting
  resources, source/release parity, and the approved cleanup set.
- Re-run release-target Plugin Eval and require zero failures, no score/grade
  regression, and a measurable reduction in active invoke cost without
  disabling natural-language routing.
- Do not change methodology/roadmap provider selection, public CLI behavior,
  project migrations, dependencies, cache state, or skill invocation policy.

## Capabilities

### New Capabilities

- `devflow-skill-portfolio`: Defines evidence-backed skill ownership,
  compatibility-safe cleanup, and progressively disclosed supporting-resource
  contracts for the DevFlow plugin.

### Modified Capabilities

- `devflow-plugin-quality`: Extends release quality requirements with portfolio
  reachability, source/release parity, and aggregate Plugin Eval budget evidence.

## Impact

- Affected source: `dev/plugins/dev-flow/skills/**`, focused DevFlow tests, and
  release synchronization inputs.
- Affected release: generated `plugins/dev-flow/skills/**` and compact packaged
  smoke coverage.
- Compatibility: no public skill name, routed capability, command behavior, or
  invocation-policy change; only unreferenced duplicated supporting files may
  be deleted.
- Dependencies and external state: no new dependency, provider activation,
  project migration, installed-cache refresh, archive, commit, or push.
