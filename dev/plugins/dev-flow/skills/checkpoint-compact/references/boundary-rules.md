# Boundary Rules

Create checkpoints after setup, codebase mapping, design, OpenSpec planning, phase planning, verification, archive, and phase ship boundaries.

Recommend compact only when the checkpoint has a clear continuation in the current thread. If the task is complete, at review/archive, or intended as a handoff/new-thread stopping point, compact is optional and should not block state updates.

Do not recommend compact for small task updates, typo fixes, tiny docs-only changes, or completed stopping points unless context is clearly degraded and work will continue immediately.
